## Обзор системы отслеживания

Система отслеживания циклонов в ArcticCyclone предназначена для связывания обнаруженных циклонов между последовательными временными шагами, создавая непрерывные треки, которые представляют жизненный цикл каждого циклона.

Основные задачи системы трекинга:

1. **Связывание точек**: Определение, какие циклоны на последовательных временных шагах принадлежат одному и тому же циклону
2. **Обработка разрывов**: Учет временных разрывов в данных или пропущенных обнаружений
3. **Кластеризация**: Устранение дублирующих обнаружений на одном временном шаге
4. **Фильтрация**: Удаление недостоверных или коротких треков

## Архитектура трекера

Центральным компонентом системы трекинга является класс `CycloneTracker`, который реализует весь процесс отслеживания.

### Основные компоненты

1. **CycloneTracker**: Основной класс трекера
2. **Кластеризация**: Методы для устранения дублирующих обнаружений
3. **Алгоритмы связывания**: Методы для связывания циклонов во времени
4. **Фильтрация**: Методы для удаления недостоверных треков

### Рабочий процесс

1. Кластеризация кандидатов на каждом временном шаге
2. Последовательное связывание кластеров между временными шагами
3. Формирование временных треков
4. Фильтрация треков по физическим критериям

## Алгоритмы трекинга

### Алгоритм ближайших соседей

Базовый алгоритм трекинга использует принцип ближайшего соседа для связывания циклонов между временными шагами.

#### Принцип работы

1. Для каждого циклона на текущем временном шаге ищется ближайший циклон на предыдущем шаге
2. Расстояние между циклонами вычисляется с использованием формулы гаверсинуса
3. Учитываются дополнительные параметры: изменение давления, временной интервал
4. Проверяются физические ограничения (максимальная скорость, изменение давления)

#### Преимущества

- Простота реализации
- Вычислительная эффективность
- Хорошо работает для непрерывных треков

#### Ограничения

- Может давать ошибки при пересечении треков
- Не оптимизирует глобальную структуру треков

### Венгерский алгоритм

Для улучшения качества трекинга используется венгерский алгоритм (алгоритм Куна-Манкреса) для оптимального назначения циклонов.

#### Принцип работы

1. Формируется матрица стоимостей связывания между всеми циклонами на текущем и предыдущем шагах
2. Стоимость вычисляется на основе расстояния, изменения давления и временного интервала
3. Применяется венгерский алгоритм для нахождения оптимального назначения
4. Проверяются физические ограничения для каждого связывания

#### Преимущества

- Глобальная оптимизация связываний
- Уменьшение количества ошибок при пересечении треков
- Более надежное связывание в сложных ситуациях

#### Ограничения

- Более высокая вычислительная сложность
- Требует больше памяти для хранения матрицы стоимостей

## Кластеризация кандидатов

На каждом временном шаге может быть обнаружено несколько близко расположенных кандидатов, которые на самом деле представляют один и тот же циклон. Система использует кластеризацию для устранения этих дубликатов.

### Алгоритм кластеризации

1. Вычисление расстояний между всеми парами кандидатов
2. Группировка кандидатов, находящихся ближе чем заданное расстояние
3. Выбор представителя кластера (обычно самый интенсивный циклон)
4. Сохранение информации о кластеризации для последующего анализа

### Параметры кластеризации

- `cluster_distance`: Максимальное расстояние между кандидатами в одном кластере (км)
- `cluster_pressure_diff`: Максимальная разность давления между кандидатами в одном кластере (гПа)

## Фильтрация треков

После трекинга применяются фильтры для удаления недостоверных или малозначимых треков.

### Критерии фильтрации

#### Минимальная продолжительность

Треки с продолжительностью меньше заданного порога удаляются. Это помогает исключить случайные обнаружения.

#### Минимальное количество точек

Треки с количеством точек меньше минимального порога считаются недостоверными.

#### Реалистичность движения

Проверяется, что скорость перемещения циклона не превышает физически возможную скорость (обычно 120 км/ч для арктических циклонов).

#### Реалистичность изменения давления

Проверяется, что скорость изменения давления находится в разумных пределах.

### Статистика фильтрации

Система ведет статистику по фильтрации:
- Количество треков до фильтрации
- Количество треков, отфильтрованных по продолжительности
- Количество треков, отфильтрованных по количеству точек
- Количество треков, отфильтрованных по реалистичности движения
- Количество треков, отфильтрованных по реалистичности давления
- Количество треков после фильтрации

## Параметры трекинга

### Основные параметры

#### max_distance

**Тип**: `float`  
**Значение по умолчанию**: `500.0`  
**Единицы**: км  
**Описание**: Максимальное расстояние между точками циклона на последовательных временных шагах. Если расстояние между циклонами превышает этот порог, они не связываются в один трек.

#### max_time_gap

**Тип**: `float`  
**Значение по умолчанию**: `12.0`  
**Единицы**: часы  
**Описание**: Максимальный временной разрыв между наблюдениями циклона. Позволяет учитывать пропущенные временные шаги или временные разрывы в данных.

#### max_pressure_change

**Тип**: `float`  
**Значение по умолчанию**: `20.0`  
**Единицы**: гПа  
**Описание**: Максимальное изменение давления между последовательными наблюдениями циклона. Это физическое ограничение помогает избежать связывания разных циклонов.

#### min_track_duration

**Тип**: `float`  
**Значение по умолчанию**: `9.0`  
**Единицы**: часы  
**Описание**: Минимальная продолжительность трека циклона. Треки короче этого значения удаляются как недостоверные.

#### min_track_points

**Тип**: `int`  
**Значение по умолчанию**: `3`  
**Описание**: Минимальное количество точек в треке. Треки с меньшим количеством точек удаляются.

#### max_cyclone_speed

**Тип**: `float`  
**Значение по умолчанию**: `120.0`  
**Единицы**: км/ч  
**Описание**: Максимальная физически возможная скорость перемещения циклона. Используется для проверки реалистичности движения.

### Параметры кластеризации

#### cluster_distance

**Тип**: `float`  
**Значение по умолчанию**: `100.0`  
**Единицы**: км  
**Описание**: Максимальное расстояние между кандидатами для объединения в один кластер.

#### cluster_pressure_diff

**Тип**: `float`  
**Значение по умолчанию**: `5.0`  
**Единицы**: гПа  
**Описание**: Максимальная разность давления между кандидатами для объединения в один кластер.

### Параметры отладки

#### debug_save_csv

**Тип**: `boolean`  
**Значение по умолчанию**: `false`  
**Описание**: Сохранять промежуточные результаты трекинга в CSV файлы для отладки.

#### debug_dir

**Тип**: `string`  
**Значение по умолчанию**: `"debug"`  
**Описание**: Директория для сохранения отладочных файлов.

## Настройка трекинга

### Через конфигурационный файл

Параметры трекинга настраиваются в секции `tracking` файла `config.yaml`:

```yaml
tracking:
  # Основные параметры трекинга
  max_distance: 600.0        # км - максимальное расстояние между точками
  max_time_gap: 18.0         # часы - максимальный временной разрыв
  max_pressure_change: 25.0  # гПа - максимальное изменение давления
  min_track_duration: 12.0   # часы - минимальная длительность трека
  min_track_points: 4        # минимальное количество точек в треке
  max_cyclone_speed: 120.0   # км/ч - максимальная физическая скорость
  
  # Параметры кластеризации
  cluster_distance: 100.0    # км - расстояние для кластеризации
  cluster_pressure_diff: 5.0 # гПа - разность давления для кластеризации
  
  # Debug опции
  debug_save_csv: false      # сохранять ли debug CSV файлы
  debug_dir: "debug"         # директория для debug файлов
  
  # Алгоритм трекинга
  algorithm: "nearest_neighbor"  # алгоритм связывания точек
  cost_weights:              # веса для расчета стоимости связывания
    distance: 1.0
    time: 1.0
    pressure: 0.5
```

### Через код

Параметры трекинга также можно настроить программно:

```python
from detection.tracker import CycloneTracker

# Создание трекера с пользовательскими параметрами
tracker = CycloneTracker(
    max_distance=500.0,           # Максимальное расстояние (км)
    max_time_gap=12.0,            # Максимальный временной разрыв (часы)
    max_pressure_change=15.0,     # Максимальное изменение давления (гПа)
    min_track_duration=6.0,       # Минимальная продолжительность трека (часы)
    min_track_points=3,           # Минимальное количество точек
    cluster_distance=75.0,        # Расстояние для кластеризации (км)
    cluster_pressure_diff=3.0,    # Разность давления для кластеризации (гПа)
    max_cyclone_speed=100.0,      # Максимальная скорость циклона (км/ч)
    debug_save_csv=True,          # Сохранять debug CSV файлы
    debug_dir="tracking_debug"    # Директория для debug файлов
)

# Отслеживание циклонов
cyclone_tracks = tracker.track(all_cyclones)

# Фильтрация треков
filtered_tracks = tracker.filter_tracks(
    cyclone_tracks,
    min_duration=12.0,  # Минимальная продолжительность (часы)
    min_points=4        # Минимальное количество точек
)
```

### Рекомендации по настройке для арктических условий

#### Для арктических мезоциклонов

- `max_distance`: 400-600 км (мезоциклоны быстро перемещаются)
- `max_time_gap`: 12-18 часов (учет возможных разрывов)
- `max_pressure_change`: 20-30 гПа (быстрые изменения давления)
- `min_track_duration`: 6-12 часов (короткие, но интенсивные системы)
- `min_track_points`: 3-4 точки
- `cluster_distance`: 75-100 км (близкие циклоны)
- `max_cyclone_speed`: 100-120 км/ч

#### Для крупных арктических циклонов

- `max_distance`: 600-800 км
- `max_time_gap`: 18-24 часов
- `max_pressure_change`: 25-35 гПа
- `min_track_duration`: 12-24 часов
- `min_track_points`: 4-6 точек
- `cluster_distance`: 100-150 км
- `max_cyclone_speed`: 80-100 км/ч

## Анализ результатов трекинга

### Метрики жизненного цикла

Для каждого трека вычисляются метрики жизненного цикла:

- **Продолжительность жизни**: Время от появления до исчезновения циклона
- **Скорость углубления**: Скорость снижения давления (гПа/ч)
- **Смещение**: Расстояние между начальной и конечной точкой трека
- **Средняя скорость**: Скорость перемещения циклона (км/ч)

### Статистика треков

Система предоставляет статистику по всем обнаруженным трекам:

- Распределение продолжительности треков
- Распределение минимального давления
- Распределение скоростей перемещения
- Распределение скоростей углубления
- Пространственное распределение циклонов

### Визуализация треков

Результаты трекинга могут быть визуализированы различными способами:

- **Карты треков**: Отображение всех треков на карте
- **Тепловые карты**: Плотность циклонов в различных регионах
- **Графики параметров**: Изменение параметров циклонов во времени
- **Статистические диаграммы**: Распределения различных метрик
